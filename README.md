# 피젯 토이

브라우저에서 돌아가는 피젯 토이 모음. 폰에서 손가락으로 만지작거리는 용도이고,
홈 화면에 설치하면 오프라인으로도 동작한다. 지금 들어 있는 것은 **탱클**, **키캡**,
**말랑이**(속·겉을 바꾸면 오르비즈 볼, 곡식 주머니, 그물망 볼, 왁뿌볼이 된다).

## 구조

한 파일(`fidget.html`) 안에 껍데기 하나와 토이 모듈들이 들어 있다. 껍데기는 렌더러,
테마, 소리, 진동, 크롬, 토이 전환을 갖고 있고, 토이는 각자 자기 씬·카메라·입력·패널을
갖는다. 두 번째 토이를 넣을 때 분리했다 — 세 번째까지 미뤘으면 두 배로 들었을 것이다.

색은 껍데기가 공용 팔레트(무지개·파스텔·네온·바다·캔디·단색)를 들고 있고, 토이는
"내가 칠하려는 것의 0~1 위치"로 색을 받아 간다. 그래서 조각 16개짜리 고리와 키 4개짜리
줄에 같은 팔레트가 그대로 쓰인다.

토이 하나는 이런 모양이다:

```js
{ scene, camera, resize(w,h), update(dt,now), down/move/up(ev),
  rows() -> [DOM],          // 튜닝 패널에 들어갈 줄들
  hud()  -> {text, warn},
  action?: {label, run} }   // 오른쪽 아래에 버튼 하나 (탱클의 "섞기")
```

## 탱클

90° 꺾인 똑같은 조각들이 이어진 것이고, 각 연결부는 **튜브 축을 중심으로 한 회전
1자유도**만 갖는다. 그래서 조각이 16개면 전체 상태는 **각도 16개**가 전부고, 모양은
거기서 순방향 운동학으로 결정론적으로 나온다. 물리 엔진은 쓰지 않는다 — 실제 탱클은
관절 마찰 때문에 민 곳만 움직이고 나머지는 모양을 유지하는 **준정적** 물체라서, 중력
달린 강체 시뮬레이션을 붙이면 오히려 축 늘어져 탱클답지 않아진다.

닫힌 고리라 각도들이 자유롭지 않고 **루프 폐쇄 제약 6개**를 만족해야 한다. 매 프레임
감쇠 최소제곱(DLS) 뉴턴으로 그 제약 위에 되돌려 놓는다. 이때 쓰는 가중치가 손맛을
정하는 핵심이다 — 손가락이 잡은 관절에 큰 가중치를 주면 그 관절은 잘 안 밀리고 보정이
나머지 고리로 퍼져나가서, 한 곳을 비틀면 고리 전체가 꿈틀거리며 받아주는 느낌이 난다.

- **강체 드리프트 제거** — 폐쇄 보정에는 모양 변화와 "고리가 통째로 움직인 양"이 섞여
  있다. 뒤쪽은 좌표 표현의 문제일 뿐인데 화면에서는 전부 헤엄치는 걸로 보인다. 매 프레임
  그 성분만 최소제곱으로 뽑아 화면 변환에서 되돌린다.
- **자기충돌** — 붙어있지 않은 조각들을 캡슐로 보고, 겹치면 관절공간에서 밀어낸다.
  그다음 폐쇄 투영이 받아주므로 둘이 싸우지 않는다.
- **연쇄 쓸기** — 손가락이 쥔 조각을 앞지르면 그 관절을 관성째 놓아주고 다음 조각을
  집는다. 한 관절이 특이점에 걸려 잠겨도 손가락이 자연히 다음으로 넘어간다.
- **특이점** — 고리가 평평하거나 완전히 접힌 자세에 가까워지면 더 못 움직인다. 버그가
  아니라 실물도 그렇다. 야코비안의 조건수를 보고 가까워질수록 뻑뻑해지게 했다.

### 조각 수

굽힘 변환 B가 `B⁴ = 항등`이라 조각 수가 4의 배수면 폐쇄 해가 자동으로 존재한다. 다만
그 해는 같은 원을 여러 바퀴 겹쳐 도는 퇴화 상태라 쓸 수 없어서, 랜덤 초기값에서 솔버로
제대로 된 모양을 찾는다. 18처럼 4의 배수가 아닌 수가 닫히는지는 보장되지 않는다 —
패널에서 조각 수를 바꾸고 **폐쇄오차**가 `0`에 머무르면 그 수는 닫히는 것이고, 숫자가
튀면 아니다.

## 키캡

키캡 누르기는 자유도 1짜리 스프링 하나라서 솔버가 없다. 재미는 전부 **힘 곡선과 소리**에
있고, 그래서 스위치 세 종류는 세 가지 메커니즘이 아니라 **세 벌의 숫자**다.

택타일 범프는 가우시안의 미분 모양으로 넣는다 — 들어갈 때는 저항하고 넘어서면 도와주는
것, 그게 "똑" 하고 넘어가는 느낌의 정체다.

```js
resist = PRELOAD + SPRING*scale*y + bump * (-d) * exp(-1.5 d²),  d = (y - 0.36)/0.16
```

주의할 점 하나: 바닥·천장 판정은 **도달하는 순간에만** 소리를 내야 한다. 누르고 있는
동안에도 손가락 힘이 계속 들어와서 속도가 매 서브스텝 다시 쌓였다가 0이 되므로, 속도만
보고 판정하면 누르고 있는 내내 초당 180번 소리와 진동이 터진다.

진동은 안드로이드만 된다. iOS Safari에는 진동 API가 아예 없어서 아이폰에서는 소리가
촉각을 혼자 감당한다.

**불빛**은 캡의 `emissive`와 캡 아래 얇은 판 두 가지로 만든다. 판은 빛을 받지 않는
`MeshBasicMaterial`인데, 그게 "빛나는 면"이 아니라 "빛 자체"로 읽히는 이유다. 밝기는
눌린 깊이를 따라가되 뗄 때는 천천히 꺼져서, 손가락을 굴리면 지나간 자리에 잔광이 남는다.

## 말랑이

압력 소프트바디다. 표면 정점이 입자이고, 메시의 모서리가 껍질이 늘어나는 걸 막고,
닫힌 메시의 **부피** 하나가 전역 제약으로 걸린다. 이 부피 항이 토이의 전부다 — 누른
자리 옆이 부풀어 오르는 것도, 떼면 다시 구로 돌아오는 것도 여기서 나온다. 사면체
메시는 필요 없다. 닫힌 표면이면 이미 부피를 갖기 때문이다.

닫힌 메시의 부피와 그 기울기:

```
V = (1/6) Σ (a × b) · c          (면마다)
6·∂V/∂a = b × c,  6·∂V/∂b = c × a,  6·∂V/∂c = a × b
```

PBD 한 번에 `λ = -(V - V₀) / Σ|∇V|²` 만큼 모든 정점을 기울기 방향으로 민다.

구는 `IcosahedronGeometry` 대신 직접 만든다. 그쪽은 인덱스가 없어서 정점이 면마다
중복되는데, 물리에는 공유 정점과 모서리 목록이 필요하다.

**손가락은 구(sphere)로 모델링한다.** 안으로 들어온 정점을 구 표면으로 밀어내기만
하면 된다. 자국이 둥글게 패이고, 껍질이 손가락에 들러붙지 않고 미끄러지는 것도
공짜로 따라온다. 입자를 목표 지점으로 끌어당기는 방식보다 훨씬 낫다.

공이 밀려 날아가지 않도록 매 서브스텝 질량중심을 원점으로 되돌린다(다른 손으로 쥐고
있는 셈). 이때 `Prev`도 같이 옮겨야 한다 — 안 그러면 되돌린 양이 속도로 둔갑한다.

### 질감 — 실물 말랑이들의 차이는 결국 하나

모찌·니도·스트레스볼·저반발 폼·슬라임을 갈라놓는 건 재료 이름이 아니라 **자국이 얼마나
빨리 사라지는가**다. 실리콘은 튕기듯 바로 돌아오고, 니도 같은 도우형은 잠깐 머물고,
저반발 폼은 몇 초에 걸쳐 천천히 올라온다.

그래서 탄성만으로는 부족하고 **소성(creep)** 이 필요하다. 모서리의 rest 길이가 지금
붙들려 있는 길이 쪽으로 흘러갔다가, 원래 길이로 천천히 기어 돌아오게 한다:

```
rest += (현재길이 - rest) * (1 - e^(-give·h))      // 눌린 모양에 굴복
rest += (원래길이 - rest) * (1 - e^(-back·h))      // 그리고 천천히 복원
```

`give = 0`이면 순수 탄성(모찌·젤), `give`가 크고 `back`이 작으면 저반발 폼, 더 극단으로
가면 슬라임. 프리셋 다섯 개가 전부 이 두 숫자와 감쇠의 조합이다.

### 속에 든 것

오르비즈 볼, 구슬 볼, 메탈릭 글리터 볼처럼 투명한 껍질 안에 뭔가 들어 있는 부류가
따로 있다. 알갱이는 각자 입자로 돌리고, **껍질 자체가 벽 역할을 한다**:

껍질은 중심에 대해 star-shaped이므로, 알갱이가 놓인 방향으로 껍질의 반지름을 찾으면
그게 그 알갱이가 넘지 못하는 벽이다. 누르면 그 방향의 벽이 안으로 들어오고, 알갱이는
자연히 옆으로 밀린다. 그물 같은 걸 따로 만들 필요가 없다.

방향별 벽은 껍질 정점 162개 중 방향이 가장 가까운 것에서 읽는다. 알갱이가 수백 개면
이게 무거워지므로, **가장 얕은 벽보다 더 안쪽에 있는 알갱이는 조회 자체를 건너뛴다.**
반짝이 380개에서는 대부분이 걸러진다.

껍질은 속이 있을 때만 반투명으로 바뀐다(속마다 불투명도가 다르다). 알갱이는 불투명이라
먼저 그려지고 껍질이 그 위에 덮인다.

**곡식/모래주머니**는 결이 다르다. 알갱이들이 서로 맞물려 굳기 때문에 **원래 모양으로
안 돌아온다.** 그건 탄성이 아니라 소성이므로 `give: 14, back: 0.02`로 표현한다 — 누른
자국이 사실상 영구히 남는다. 소리도 사락사락이 아니라 **바삭거림**이라, 짧은 클릭을
촘촘하게 연달아 낸다. 알갱이 속도가 아니라 **껍질이 변형되는 속도**로 몰아서, 누르는
동안 계속 바스락거리고 손을 떼면 바로 조용해진다. 곡식은 눈보다 손과 귀로 느끼는
물건이라 껍질을 거의 불투명하게 두고 품을 소리 쪽에 썼다.

### 그물망 — 속이 아니라 바깥

그물은 **늘어나지 않는 바깥 구속**이다. 모델은 한 줄이면 된다: 그물 위의 정점은 안으로는
가도 **밖으로는 못 간다.** 그 사이 정점들은 자유로우니, 부피 제약이 밀어내면 구멍으로
비집고 나온다. 그물을 따로 만들 필요가 없다.

그물 위치는 **쉬고 있는 구**에서의 위도·경도로 정한다(경선 6, 위선 4). 변형된 위치가
아니라 쉬는 위치를 쓰므로 무늬가 껍질에 박혀서 같이 움직인다. 그물은 정점 색으로
칠한다. 선을 그리려면 정점이 촘촘해야 해서, 그물을 켜면 해상도가 높음으로 올라간다.

### 왁스 (왁뿌볼)

말랑한 속을 왁스로 코팅해 굳힌 뒤 눌러서 부수는 물건이다. 핵심은 **단단하다가 갑자기
안 단단해지는 것**이고, 그래서 모델도 거기에 맞춘다.

왁스 껍데기를 26조각으로 나눈다. 조각 나누기는 구 위에 피보나치로 뿌린 씨앗에 각 면을
가장 가까운 씨앗으로 배정하는 식이라, 경계가 불규칙해서 실제로 왁스가 깨진 것처럼
보인다.

**조각이 붙어 있는 동안 그 조각이 덮은 코어 정점들을 쉬는 위치로 끌어당긴다**(반복마다
55%). 그래서 왁스가 덮인 곳은 눌러도 안 들어간다. 그 끌어당기기 전의 어긋난 양이 곧
그 조각이 받는 힘이고, 한계를 넘으면 조각이 떨어져 나간다 — 지오메트리를 그 순간
모양으로 얼려 중심을 빼고, 속도와 회전을 줘서 날려 보낸다.

조각 하나가 떨어지면 **이웃 조각의 한계를 55%로 낮춘다.** 그래서 한 번 금이 가면
주르륵 번진다. 실물의 "뽀각" 하고 연달아 깨지는 느낌이 여기서 나온다.

실물은 한 번 부수면 끝이지만 여기선 **새 공** 버튼으로 다시 코팅한다. 같은 버튼이
모래주머니처럼 안 돌아오는 질감도 되돌린다.

## 카메라는 가만히 있어야 한다

세 토이 모두에서 같은 실수를 반복했다. 매 프레임 "지금 모양이 딱 들어가는 거리"를
다시 계산하면 화면이 끊임없이 숨을 쉰다. 규칙:

- **크기가 변하지 않는 토이**(키캡, 말랑이)는 프레임을 **고정**한다. 말랑이는 구라서
  거리가 화면 비율만의 함수이고, 키캡은 보는 각도가 바뀔 때만 다시 맞춘다.
- **크기가 정말 변하는 토이**(탱클)만 따라가되 **멀어지기만** 한다. 잘릴 때 물러나고,
  다시 가까워지지는 않는다. 섞기·화면 회전에서만 다시 맞춘다.

말랑이에서 이걸 놓쳤을 때 증상은 누를 때마다 카메라가 0.5%씩 물러나고 돌아오지 않는
것이었다(5.076 → 5.087 → 5.106). 한 번은 안 보이지만 놀다 보면 공이 계속 작아진다.

## 폴더

```
fidget.html      소스. 여기만 고치면 된다
build-pwa.ps1    fidget.html → docs/index.html
serve.ps1        docs/ 를 http://localhost:8765 로 띄우는 정적 서버
docs/            빌드 결과. GitHub Pages가 서빙하는 폴더
```

`fidget.html`은 문서 뼈대(`<!doctype>`, `<head>`)가 없다. Artifact 플랫폼이 퍼블리시할 때
붙여주기 때문이다. `build-pwa.ps1`이 그 부분과 PWA 설정을 더해 `docs/index.html`을 만든다.

## 고치고 다시 올리기

```powershell
.\build-pwa.ps1          # fidget.html -> docs/index.html
.\serve.ps1              # http://localhost:8765 에서 확인
```

바꾼 걸 올릴 때는 **`docs/sw.js`의 `CACHE` 값을 반드시 올릴 것.** 안 그러면 이미 설치한
폰은 서비스워커 캐시에 있는 옛 빌드를 계속 쓴다. 개발 중에도 같은 함정에 빠지므로,
브라우저에서 확인할 때는 쿼리를 붙이거나(`?v=2`) 서비스워커를 해제하고 볼 것.

주의: `build-pwa.ps1`은 `Get-Content -Raw -Encoding UTF8`로 읽는다. `-Encoding UTF8`을
빼면 Windows PowerShell이 시스템 코드페이지로 읽어서 JS 문자열 안의 한글까지 깨뜨리고,
그대로 문법 에러가 난다.

## 배포

GitHub Pages: Settings → Pages → Source `Deploy from a branch`, Branch `main` / `/docs`.
`docs/.nojekyll`이 있어야 Jekyll이 파일을 건드리지 않는다.

경로는 상대 경로로만 써서 `user.github.io/저장소이름/` 같은 하위 경로에서도 그대로 동작한다.

## 아직 안 된 것

- 탱클의 자기충돌은 강체 충돌이 아니라 "겹치면 밀어내기"라서 빠르게 밀면 살짝 파고든다.
- 키캡은 아직 모양이 한 종류다. 각인·프로파일·재질은 없다.
- 말랑이는 자기 자신과 충돌하지 않는다. 깊게 누르면 반대쪽 껍질을 통과할 수 있다.
- 그물 무늬는 위도·경도라 극에서 선이 모인다. 정이십면체 모서리를 따라가면 고르겠지만
  그 그물은 코가 촘촘해서 구멍이 거의 안 남는다.
- 곡식의 알갱이는 서로 밀어내지 않는다(300개라 O(n²)가 아깝다). 보이는 건 분포뿐이고
  맞물리는 느낌은 껍질의 소성이 낸다.
- 두 손가락 앵커 비틀기, 모양 URL 공유는 아직 없다.
